# 部署硬件与运行环境要求

> 适用版本：以当前仓库版本为准。以下是容量规划建议，不是程序硬编码的最低限制。

## 一、基础依赖

| 项目 | 要求/建议 |
|---|---|
| 操作系统 | 64 位 Linux 服务器优先；Docker 也可运行于其他受支持的容器宿主机 |
| 容器运行时 | Docker；生产环境推荐 Docker Compose 或等价编排 |
| 数据库 | 内置 SQLite，或 MySQL ≥ 5.7.8、PostgreSQL ≥ 9.6；生产环境优先独立数据库 |
| 缓存 | Redis 按缓存、限流、多机和会话场景启用；多机部署建议使用共享 Redis |
| 网络 | 能访问上游 AI 服务、数据库、Redis 和镜像仓库；必须支持 DNS、TLS 和稳定出站连接 |
| 存储 | `/data`、数据库、日志和备份必须持久化；不要把生产数据只放在容器可写层 |
| 反向代理 | 生产建议使用 Nginx、Caddy、云负载均衡或同类入口，启用 HTTPS 和请求体/超时配置 |

SQLite 适合开发、演示和低并发场景。高并发、多节点或较大日志量场景应使用 MySQL/PostgreSQL，并评估独立日志库或 ClickHouse 的需求。

## 二、容量建议

| 场景 | 网关计算 | 内存 | 系统盘/数据盘 | 适用范围 |
|---|---:|---:|---:|---|
| 开发与功能验证 | 1–2 vCPU | 2–4 GB | 20 GB SSD | 单人、低并发、SQLite、短期日志 |
| 小规模生产 | 2–4 vCPU | 4–8 GB | 50–100 GB SSD | 小团队、有限并发、独立备份 |
| 中规模生产 | 4–8 vCPU | 8–16 GB | 100 GB 以上 SSD | 多用户、多渠道、较长日志和 Redis/独立数据库 |
| 大规模生产 | 按压测扩容 | 按数据库/并发扩容 | 按日志和备份增长 | 多节点、负载均衡、独立数据库/Redis、监控告警 |

这些数字只描述 New API 网关本身，不包含本地部署的大模型推理服务。实际需求会随并发数、流式连接数、请求体大小、图片/视频响应大小、日志保留周期、数据库索引、Redis 数据量和上游延迟变化。

## 三、Docker Compose 资源注意事项

仓库根目录 [`docker-compose.yml`](../docker-compose.yml) 默认包含：

- `new-api` 网关容器，端口 `3000`。
- PostgreSQL 数据库。
- Redis。
- `./data` 和 `./logs` 持久化目录。

部署前必须修改 Compose 中示例数据库密码和 Redis 密码。不要直接将示例凭据用于公网生产环境。使用 SQLite 时仍要挂载 `/data`；使用 MySQL/PostgreSQL 时要配置正确的 `SQL_DSN`。

## 四、多机与高可用

多节点部署至少需要：

1. 所有节点使用一致的 `SESSION_SECRET`，保证登录会话可验证。
2. 共享的 Redis；按部署方式配置 `CRYPTO_SECRET`，保证加密数据可解密。
3. 外部 MySQL/PostgreSQL 和持久化备份，不让每个容器使用独立 SQLite。
4. 反向代理或负载均衡，并配置 WebSocket、流式响应、上传体积和超时。
5. 统一日志、节点名、监控指标和告警。
6. 数据库、Redis、配置和 `/data` 定期备份并演练恢复。

## 五、GPU 是否必需

New API 作为 API 网关、鉴权、路由、计费和日志服务时不要求 GPU。只有在同一套基础设施中额外部署本地模型推理服务时，才根据模型大小、量化方式、上下文长度和并发另行规划 GPU 显存、CPU、内存和磁盘。

## 六、安全基线

- 管理入口不要直接暴露到公网；使用 HTTPS、访问控制和强管理员密码。
- 修改所有 Docker Compose 默认密码和示例密钥。
- API Key 使用密钥管理系统、环境变量或受控后台录入，不写入镜像和 Git。
- 日志脱敏，限制管理员和运维人员的日志访问权限。
- 对上游连接启用 TLS，定期轮换渠道密钥。
- 为数据库、Redis、日志和备份配置最小权限、容量告警和保留周期。
