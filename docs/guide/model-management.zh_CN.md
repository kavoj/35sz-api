# 模型添加与管理指南

> 适用版本：以当前仓库版本为准。管理端字段和权限以当前部署版本为准。

模型管理解决“平台展示什么模型、模型属于什么能力、请求应该路由到哪个上游名称”三个问题。**渠道模型列表**决定上游可用范围，**模型管理/模型元数据**决定平台侧的展示、能力标签和价格关联，两者需要同时正确。

## 一、模型与渠道的关系

- **渠道**：保存上游地址、密钥、模型列表、分组和路由策略。
- **模型名**：调用方发送给 New API 的 `model` 值。
- **上游模型名**：通过模型映射转换后发送给渠道的模型 ID。
- **模型类型**：标识文本、图片、视频、音频、Embedding、Rerank 等能力，影响端点和测试请求。
- **模型映射**：当平台模型名与上游模型名不一致时使用，例如平台统一名 `my-chat-model` 映射到供应商的真实 ID。

同一个平台模型可以配置多个渠道。路由层会结合渠道状态、分组、优先级、权重和失败重试选择可用上游。

## 二、添加模型的建议流程

1. 先在 **渠道** 中创建或编辑上游渠道。
2. 在渠道的 **模型列表** 中填入上游实际可用模型 ID，并保存。
3. 在模型管理中确认模型类型、能力标签和供应商元数据。
4. 如果平台名与上游名不同，配置模型映射，并确认映射方向。
5. 为模型配置价格，参阅[价格与计费指南](pricing-and-billing.zh_CN.md)。
6. 创建一个受限测试令牌，调用模型并查看日志。

模型同步/获取模型功能只能获得上游返回的模型，不能替代上游订阅授权。某些供应商不会开放模型列表，此时应手工填写并用真实请求验证。

## 三、模型类型与端点

| 能力 | 常见端点 | 调用方式 |
|---|---|---|
| 文本聊天 | `/v1/chat/completions` | OpenAI Chat Completions |
| Responses | `/v1/responses` | OpenAI Responses |
| 图片生成 | `/v1/images/generations` | OpenAI 图片请求 |
| 视频任务 | 以供应商适配器和任务接口为准 | 创建任务后查询任务状态 |
| 语音合成 | `/v1/audio/speech` | 文本转音频 |
| 语音识别 | `/v1/audio/transcriptions` | multipart 音频上传 |
| Embedding | `/v1/embeddings` | 文本向量化 |
| Rerank | `/v1/rerank` | 文档重排序 |
| Realtime | WebSocket/Realtime 入口 | 实时会话 |

端点不应只根据名称猜测。模型类型、渠道类型和适配器共同决定最终上游路径；修改模型类型后要重新测试。

## 四、映射与排错

### 模型不存在或 404

- 检查调用的 `model` 是否出现在渠道模型列表。
- 检查模型映射是否把平台名转换为正确的上游 ID。
- 检查 Base URL 是否重复拼接 `/v1`、`/api/v3` 或 Agent Plan 路径。
- 检查模型是否需要专用渠道类型，而不是普通 OpenAI 兼容渠道。

### 调用到了错误渠道

- 检查渠道分组和令牌分组。
- 检查渠道优先级和权重。
- 检查渠道是否被自动禁用。
- 检查失败重试配置和使用日志中的 `channel_id`。

### 模型改名后的缓存

保存模型或映射后重新打开模型详情并执行一次测试。若管理端仍显示旧数据，刷新页面；服务端缓存刷新以当前版本的模型管理逻辑为准。不要直接修改数据库绕过后台校验。

## 五、接口参考

管理员自动化管理渠道和模型时，请以 [`docs/openapi/api.json`](../openapi/api.json) 中的 `/api/channel/`、`/api/model/` 等定义为准。API Key 应通过安全的环境变量、密钥管理系统或受控 CI Secret 注入，不要提交到示例文件。
